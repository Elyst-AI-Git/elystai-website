# Home page reference brief

*Prepared 29 August 2026. https://listai.com was not reachable during this pass, so the current-page audit uses the root checkout's / route plus the website brief in Work OS. The checkout is branded Elyst AI and points to elystai.com; confirm the intended public domain before implementation.*

## Current page read

The working page has a clear conversion story: a large split hero with the animated green dither mark, a dark floating navigation bar, an off-white/soft-green section rhythm, large Manrope headings, and a dark starfield footer. The visual system is distinctive and restrained. The problem is not the visual identity; it is that the page becomes mostly text and bullets after the hero.

The content is already pointed in the right direction:

- The hero says Elyst finds the work worth improving, builds the system, and trains the team.
- The “bought the subscriptions / work has not changed” section names the real problem.
- “Audit → Build → Handover” is a strong, understandable spine.
- The fit language, human ownership, safeguards, and “say when AI is not the answer” principle build trust.
- The evidence section still depends on unresolved proof and an unverified “50+ companies” claim.
- The secondary training strip is useful, but should remain clearly secondary to implementation.

## Recommended changes, in order

1. **Make the first screen more buyer-specific.** Keep the current hero and dither mark, but add a short line naming the work Elyst fixes: lead intake and follow-up, RFQ/quoting, appointments, documents, and reporting. These are examples, not a promise to serve every sector.
2. **Turn the three-step block into an output chain.** Audit should show a workflow map and first opportunity; Build should show a tested working slice; Handover should show training, runbook, access transfer, and a named owner.
3. **Move real evidence higher.** Use the permissioned Aug 18 training proof now, then add the first implementation proof when it exists. If proof is not ready, show a clearly labelled sample artefact rather than a statistic.
4. **Use one GCC-relevant mini-case without narrowing the company.** A UAE real-estate lead flow and a trade/logistics RFQ flow would make the offer tangible while keeping the homepage sector-neutral.
5. **Keep the “not for everyone” idea.** The current fit language is a differentiator. Add one sentence that high-risk decisions retain human approval.
6. **Replace unsupported scale claims.** Do not publish “50+ companies” until the number and wording are verified. Early proof should be specific, permissioned, and small.
7. **Give the visual system more information to carry.** Keep the dither as the homepage’s signature visual. Add one simple workflow diagram or sanitised output preview below it; avoid filling the page with decorative cards.
8. **Keep CTA intent clean.** The primary CTA should be “Book an audit call” and ask for one workflow. Training remains a secondary route for teams that need capability before implementation.

The homepage should make one sentence believable: *bring us one costly workflow; we will tell you whether to fix the process, adopt an existing tool, or build a small system your team can own.*
